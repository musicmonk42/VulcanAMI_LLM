# CSIU Phase 9 dataflow note

## Before repair

The existing CSIU path was present but not reliably safe or inspectable. `SelfImprovementDrive.__init__` enabled CSIU switches from environment variables, initialized mutable `w1`-`w9` weights, set `_csiu_U_prev` to `-1000.0`, and constructed the global enforcer when import succeeded. Persisted weights were silently merged into defaults. `_safe_get_metric` fell back to cached/default synthetic values, so `_collect_telemetry_snapshot` could influence plans without real telemetry. `_csiu_utility` mixed deltas and absolute levels with inconsistent signs. `_csiu_update_weights` directly changed active weights using the same utility they defined. `_csiu_pressure` depended on unbounded logistic/exp-style math. `_csiu_regularize_plan` had an uncapped inline fallback if enforcement was unavailable and mutated shallow plan copies. The `step()` call site calculated CSIU only after plan generation and before `process_plan`, caught failures as debug-only non-fatal events, and did not return typed decisions. `CSIUEnforcement` checked cumulative caps before the candidate effect was included, kept restart-sensitive in-memory history, hid CSIU details in internal metadata/debug logs, and the singleton silently reused the first config.

## After repair

`SelfImprovementDrive` still owns CSIU orchestration and `CSIUEnforcement` still owns typed enforcement/accounting. The drive now assembles strict `CSIUMetricSnapshot` objects from real aggregate provider data only. Missing providers, missing metrics, partial snapshots, stale windows, insufficient samples, invalid ranges, and provider exceptions produce deterministic no-influence status events. The first valid snapshot establishes the baseline and produces zero pressure. Subsequent valid snapshots use normalized directional utility: positive is improvement for all metrics. EWMA uses validated alpha and pressure uses bounded `tanh`. Active CSIU weights are immutable policy; telemetry may create weight proposals but cannot activate them. Regularization is applied only through `CSIUEnforcement`, to a closed set of influence fields, on a deep copy, with typed `CSIUDecision` results and prospective cumulative cap reservation under one lock. Missing enforcement returns the original plan unchanged with an explicit reason. The drive's auto-apply route now fails closed unless a governed proposal, governed policy, audit owner, and `GovernedSelfImprovementTransaction` are available. CSIU alignment output is an inspectable proposal object targeting the exact active alignment digest; it never calls activation and must be reviewed through ordinary alignment CAS.
